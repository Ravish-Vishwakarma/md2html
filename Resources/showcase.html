1. Inline styles#

Plain text with bold, italic, bold italic, strikethrough, highlight, inline code, code with a ` backtick, and a link.

Emphasis rules: snake_case_names stay intact, arithmetic like 2 * 3 = 6 and a * spaced * asterisk are literal, and *escaped stars* come through as text.

Anything that is not a tag stays escaped, so a & b and 5 < 6 remain text.

2. Embedded HTML#

Inline tags pass straight through: H2O, HTML, and styled spans all survive. Attributes with either quote style are kept verbatim, so a tag keeps its exact markup.

Bare angle brackets and comparisons are still escaped, as in a < b and 3 <3. Self-closing and void tags are fine:

Only trust the Markdown you convert

Embedded HTML is copied through verbatim, exactly like GitHub-flavoured

Markdown. That means a <script> or onerror attribute in the source will

run in the generated page. Do not convert untrusted Markdown.

List callouts#

Put a special character straight after the list marker and the item becomes a styled callout. The character itself never shows up in the output, and the rest of the item is still ordinary inline Markdown.

  • Normal item
  • Important item
  • Question item
  • Idea item
  • Success item
  • Warning item

The default mapping is ! note, ? question, * tip, + success and ~ warning. Callouts work on ordered items, on tasks, and at any nesting depth:

  1. an ordered callout
  2. with bold and code inside
  3. a callout that is also a task
  • a callout with children
    • a plain child item
    • a nested callout keeps its own accent
    • and a nested task

Two rules keep the syntax honest: the marker needs a space after it, and only configured characters count. Both of these stay plain items:

  • !no space after the marker
  • @ an unconfigured character

Each type has its own colour, and md2html.conf can remap the characters or set a custom accent:

conf
# md2html.conf
! note
? danger
% bug #e0407a

The file is looked for next to the Markdown source first, then in the current directory. Any character may be mapped, and names left out of the file keep their defaults.

8. Images#

Images are capped at the text column width and keep their aspect ratio, so a wide picture shrinks to fit instead of stretching the page.

The alt text is printed underneath the picture in its own bordered bar. An optional title is still kept as a tooltip.

An image with no alt text is treated as decorative, so no caption bar is drawn at all:

Images load lazily, and one that fails to load shows its alt text instead of a broken icon.

Known limitations#

These are not implemented and render as literal markdown:

  • Lists, tables or code fences inside a callout body (every > line becomes its own paragraph)
  • Reference-style links and images ([text][ref], ![alt][ref])
  • Indented four-space code blocks
  • Hard line breaks via trailing two spaces
  • Syntax highlighting tokens inside fences
  • Markdown syntax inside an embedded HTML block; those lines are copied as plain markup, exactly as GitHub-flavoured Markdown behaves. Only a blank line closes the block
